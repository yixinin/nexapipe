## 详述

### H1. 2FA 锁定从未触发

- `ClientAuth::record_failure` 与 `record_success` 已经实现，写 `failed_attempts` /
  `locked_until`，并在 `failed_attempts >= max_attempts` 时设置 `locked_until`。
- `TotpValidator::record_failure` 也实现了，但 `perform_authentication`
  (`conn/mod.rs:298-395`) 的 Step 4 只调用了 `validate(...)`，失败分支只
  返回 `AuthMessage::Failed { reason: "Invalid TOTP code" }`：
  ```rust
  let validator = TotpValidator::new(config.clone());
  let is_valid = validator.validate(&client_id, &totp_code).unwrap_or(false);
  ```
- `validate` 拿到的是 `&AuthConfig`（不可变），即便补上 `record_failure` 调用，
  修改的也只是这份克隆，`Arc<RwLock<AuthConfig>>` 与磁盘 `config.toml` 都看不到。
- `config_watcher`（`config_watcher/mod.rs:30-67`）只做"文件变更 → 重读"，
  完全没有写回能力；`failed_attempts` 与 `locked_until` 即使能改，也只活在
  进程内存里。
- 影响：6 位 TOTP = 10⁶ 码值，`window=1` 给 ±30s，理论穷举时间极短；
  现有配置中的 `max_attempts = 5` / `lockout_duration = 300` 完全没生效。
- 触发路径：6 次错误密码尝试 → 服务端接受 → 没有进一步防御。
- 顺手发现：`unwrap_or(false)` 把 `InvalidSecret` / `TotpCreationFailed`
  / `ClientNotFound` / `LockedOut` 全部折成"验证码错误"，运维看不到
  配置损坏或客户端被锁。

### H2. Auth challenge / timestamp 是装饰品

- 服务端 `conn/mod.rs:328` 生成 32 字节 nonce；客户端
  `crates/nexapipe-client/src/auth.rs:182-185` 收到后 `let _nonce = nonce`
  然后丢弃，紧接着 `generate_code()` 直接生成 TOTP。
- 两端的 `timestamp`（`crates/nexapipe/src/auth/protocol.rs:17,26`；
  `crates/nexapipe-client/src/auth.rs:149-152,191-194`）被服务端用
  `_timestamp` 解构丢弃，客户端原样回传。
- 影响：截获一次 AUTH_RESPONSE 后 30s ± 1 step 窗口内可任意重放到任何
  endpoint。Challenge 增加了 1 个 RTT 但不提供任何绑定能力。

### H3. TOTP secret 进入 Android 自动备份

- `AndroidManifest.xml:20` `android:allowBackup="true"`。
- `backup_rules.xml` 与 `data_extraction_rules.xml` 是空模板（仅注释）。
- `SettingsManager.kt:11,67-78` 把 `KEY_2FA_SECRET` 原样存进
  `SharedPreferences("NexaPipeSettings", MODE_PRIVATE)`。
- 影响：① Google Drive 自动备份会带走 secret；② Android 12+ 设备间迁移
  也会带上；③ 第三方备份工具能读到明文。

### H4. 相机分析线程直接写 Compose 状态 / Toast

- `QrScannerDialog.kt:130`：`analysisExecutor = Executors.newSingleThreadExecutor()`
- `QrScannerDialog.kt:182-189`：`onDecoded(text)` 触发 `currentOnResult.value(text)`
  即 `VpnControlScreen` 中传入的闭包，闭包里写 `pendingTwoFactorImport` /
  `pendingInviteImport`（`mutableStateOf`），并 `Toast.makeText(...).show()`。
- 影响：① Compose `mutableStateOf` 在非主线程写入是常见
  `IllegalStateException` 源；② `Toast.makeText` 在非 Looper 线程只是
  `Log.w` 一行就吞掉，错误信息用户看不到。

### H5. Ticket 邀请静默失败

- `applyInviteImport`（`VpnControlScreen.kt:133-140`）对 `InviteTarget.Ticket`
  返回 `"This invite carries an endpoint ticket, which cannot be stored here..."`
- 调用点 `:977-978` 把返回值丢掉：Ticket 又恰好不带 2FA / relay 参数，
  `inviteConflicts` 通常返回空，落到"看似成功"分支并显示
  "Imported endpoint …"。但 endpoint 根本没存。
- 影响：用户以为导入成功，实际什么也没存。

### M1. Kotlin 与 Rust 对 relay 的校验不一致

- Rust `with_relay`（`provisioning.rs:259-267`）：要求 `url::Url::parse(relay)` 成功。
- Kotlin `EndpointInviteCodec.parse`（`EndpointInvite.kt:157-159`）：只判 `contains("://")`。
- `x://` 在客户端通过，到服务端被拒；用户体验是"扫完没动静"。

### M2. `AuthError` 被静默折成"验证码错误"

- `conn/mod.rs:368` `unwrap_or(false)`：`ClientNotFound` / `LockedOut` /
  `InvalidSecret` / `TotpCreationFailed` 全部统一返回 `AuthMessage::Failed`
  理由为 `"Invalid TOTP code"`。
- 影响：secret 配置损坏时运维无从察觉；客户端被锁定时无法区分。

### M3. `digits` 范围校验宽于服务端

- Rust `InviteTotp::with_params`（`provisioning.rs:177-179`）：`digits` 必须
  ∈ `[6, 8]`。
- Kotlin `parseTotp`（`EndpointInvite.kt:228-231`）：`readInt` 仅要求 `> 0`。
- 影响：扫到 `digits=10` 的 invite，Android 弹"本地不兼容"告警继续导入，
  服务端直接拒绝。两边行为不一致。

### L1. `QrCodeImage` 安静区只有 1 模块

- `QrCodeImage.kt:71` `EncodeHintType.MARGIN to 1`，外面靠 `Surface` 补白。
- 与服务端 `qr.rs:19` `QUIET_ZONE = 4` 不一致。
- QR Code 2009 规范建议 4 模块；屏幕较小或远距离扫描的机型可能拒扫。

### L2. 每次新连接深克隆整张 `AuthConfig`

- `conn/mod.rs:367` `TotpValidator::new(config.clone())`，含 `HashMap<String, ClientAuth>`
  整份拷一份。
- 同时与 H1 的 `record_failure` 设计冲突：`TotpValidator` 持 `&AuthConfig` 即可，
  写时拿外层 `RwLock` 的写锁即可。

### L3. `applyTwoFactorImport` 走的就是 H4 路径

- 与 H4 是同一根因；从分析线程回调里直接写 Compose state + Toast。

### L4. `OtpAuth.clientIdFrom` 在 issuer 不匹配时的退化策略

- `OtpAuthUri.kt:179-190`：当 label 含冒号但 issuer 不匹配时退化到
  "找第一个冒号"，可能与用户本意不符。安全无影响，但语义与 Rust 不一致。

### L5. `addLog` 把 client id 写进 `Log.d`

- `VpnViewModel.kt:156,165`：relay URL / 2FA client id 进 `Log.d`。
- secret 本身没泄露；debug 包 `Log.d` 默认可见。
