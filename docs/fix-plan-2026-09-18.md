## H1. 2FA 锁定从未触发（安全 + 功能 break）

### 改动

**文件**：`crates/nexapipe/src/conn/mod.rs`、`crates/nexapipe/src/auth/totp.rs`、
`crates/nexapipe/src/config_watcher/mod.rs`、`crates/nexapipe/src/auth/config.rs`

要点：
1. 把 `AuthConfig` 持久化所需的写回机制补齐。`ConfigWatcher` 已知持有
   路径，建议加一个 `save_auth(&AuthConfig) -> Result<()>`，写回时仅
   序列化 `[auth]` 表，避免覆盖其他正在被编辑的字段。
2. `perform_authentication` 改为接收 `Arc<tokio::sync::RwLock<AuthConfig>>`
   而非 `&AuthConfig`。Step 4 改成：

```rust
// Step 4: Validate TOTP code
let (is_valid, lockout_reason) = {
    let cfg = auth_cfg_arc.read().await;
    let validator = TotpValidator::new(&cfg); // 改为不可变借用
    let outcome = validator.validate(&client_id, &totp_code);
    match outcome {
        Ok(true) => (true, None),
        Ok(false) => (false, None),
        Err(AuthError::LockedOut) => (false, Some("locked out")),
        Err(AuthError::ClientNotFound) => {
            tracing::warn!("Auth: unknown client_id '{}' from {}", client_id, peer);
            return Err(anyhow::anyhow!("unknown client"));
        }
        Err(AuthError::InvalidSecret) => {
            tracing::error!(
                "Auth: client '{}' has an invalid Base32 secret — refusing silently",
                client_id
            );
            return Err(anyhow::anyhow!("server config error"));
        }
        Err(e) => {
            tracing::warn!("Auth: unexpected error for client '{}': {:?}", client_id, e);
            return Err(anyhow::anyhow!("auth failed"));
        }
    }
};

if !is_valid {
    let mut cfg = auth_cfg_arc.write().await;
    if let Some(client) = cfg.clients.get_mut(&client_id) {
        client.record_failure(cfg.max_attempts, cfg.lockout_duration);
    }
    // 写回磁盘
    if let Err(e) = config_watcher.save_auth(&cfg) {
        tracing::warn!("Auth: failed to persist lockout state: {}", e);
    }
}
```

3. `TotpValidator` 的 API 改为不可变：

```rust
pub struct TotpValidator<'a> {
    config: &'a AuthConfig,
}

impl<'a> TotpValidator<'a> {
    pub fn new(config: &'a AuthConfig) -> Self { ... }
    pub fn validate(&self, client_id: &str, code: &str) -> Result<bool, AuthError> { ... }
    // 不再有 record_failure / record_success，由调用方直接操作 &mut AuthConfig
}
```

4. `ClientAuth::record_failure` 的逻辑保持不变，但调用者需要保证持有
   `&mut AuthConfig`。

### 验证

- 新增 `crates/nexapipe/tests/two_factor_lockout.rs`：配置 `max_attempts=3`、
  `lockout_duration=10`，跑 5 次错误码；预期前 3 次 `AUTH_FAILED`，第 4 次
  `LockedOut`。
- 回归测试 `cargo test --workspace`。

## H2. Auth challenge / timestamp 是装饰品

### 改动

**文件**：`crates/nexapipe/src/auth/protocol.rs`、
`crates/nexapipe-client/src/auth.rs`、`crates/nexapipe/src/conn/mod.rs`

要点：把 nonce 和 timestamp 真正用上。两种路线，**推荐 B**：

#### 路线 A：去 challenge（最小改动）

1. 把 `AuthMessage::Start` / `Response` 中客户端回传字段简化为
   `{ client_id, totp_code }`；服务端不再发 `Challenge`。
2. 客户端 `auth.rs` 砍掉收 challenge 的部分。
3. 缺点：仍然没有防重放。

#### 路线 B：把 nonce HMAC 进 TOTP（推荐）

1. `auth/protocol.rs` 加一个新变体或扩展 `Response`：

```rust
Response {
    client_id: String,
    totp_code: String,
    /// HMAC-SHA256(shared_secret_with_server, nonce || timestamp)
    /// 客户端和服务端共享 secret 来自 `auth.clients.<id>.secret`
    signature: Vec<u8>,
}
```

   `shared_secret` 直接复用 TOTP Base32 secret（同一个 `auth.clients.<id>.secret`）。

2. 服务端 `perform_authentication`：发完 challenge 后记录 `{nonce, timestamp}`
   到 in-memory map（key=`client_id`，value=`(nonce, timestamp, expiry)`）；
   收到 Response 时取出对应记录，先验 HMAC 再校验 TOTP。

3. 客户端 `auth.rs`：收到 challenge 后计算 `signature`，连同 `totp_code` 一起发回。

4. `timestamp` 在服务端做 ±30s 窗口校验；超过即拒。

### 验证

- 单元测试：服务端换 nonce 后旧 response 验签失败；
- 集成测试：重放截获的 response 应被拒；
- `timestamp` 偏离 ±30s 被拒。

## H3. TOTP secret 进入 Android 自动备份

### 改动

**文件**：
- `ui-android/.../AndroidManifest.xml`
- `ui-android/.../res/xml/backup_rules.xml`
- `ui-android/.../res/xml/data_extraction_rules.xml`
- `ui-android/.../SettingsManager.kt`

要点：
1. **首选**：把 `KEY_2FA_*` 从 `SharedPreferences` 搬到 `EncryptedSharedPreferences`
   （`androidx.security:security-crypto`），用 `MasterKey.Builder(context).setKeyScheme(AES256_GCM).build()`。
   `SettingsManager` 增加一个独立的 `secretPrefs`，主 prefs 仅保留非敏感配置。

```kotlin
class SettingsManager(context: Context) {
    private val masterKey = MasterKey.Builder(context)
        .setKeyScheme(MasterKey.KeyScheme.AES256_GCM)
        .build()

    private val secretPrefs: SharedPreferences = EncryptedSharedPreferences.create(
        context,
        "NexaPipeSecrets",
        masterKey,
        EncryptedSharedPreferences.PrefKeyEncryptionScheme.AES256_SIV,
        EncryptedSharedPreferences.PrefValueEncryptionScheme.AES256_GCM
    )

    fun saveTwoFactorConfig(...) {
        secretPrefs.edit()
            .putBoolean(KEY_2FA_ENABLED, enabled)
            .putString(KEY_2FA_CLIENT_ID, clientId)
            .putString(KEY_2FA_SECRET, secret)
            .putString(KEY_2FA_ALGORITHM, algorithm)
            .apply()
    }
    // 加载器同理改为读 secretPrefs
}
```

2. 显式排除明文 prefs 的备份：

```xml
<!-- backup_rules.xml -->
<full-backup-content>
    <exclude domain="sharedpref" path="NexaPipeSettings.xml"/>
</full-backup-content>
```

```xml
<!-- data_extraction_rules.xml -->
<data-extraction-rules>
    <cloud-backup>
        <exclude domain="sharedpref" path="NexaPipeSettings.xml"/>
    </cloud-backup>
    <device-transfer>
        <exclude domain="sharedpref" path="NexaPipeSettings.xml"/>
    </device-transfer>
</data-extraction-rules>
```

3. 如果不想引入 androidx.security 依赖，至少保留 (2)：把 `KEY_2FA_*` 全部
   从 `NexaPipeSettings.xml` 挪到独立文件 `NexaPipeSecrets.xml`，并在两份
   `backup_rules.xml` 中排除它。这一步不改代码逻辑、但把"secret 进备份"的
   路径堵上。

- `adb shell bmgr backupnow com.nexa.pipe` 看 `bmgr` 不包含 secret 文件。

## L4. `OtpAuth.clientIdFrom` 在 issuer 不匹配时的退化策略

### 改动

**文件**：`ui-android/.../otp/OtpAuthUri.kt`

要点：当 issuer 已设置但 label 前缀不匹配时，返回失败（与 Rust 端
`provisioning.rs::client_id_from_label` 对齐）：

```kotlin
private fun clientIdFrom(label: String, issuer: String?): String {
    if (label.isEmpty()) return ""
    val colon = label.indexOf(':')
    if (colon < 0) return label.trim()  // 没有 colon，整段就是 client id
    if (issuer == null) {
        return label.substring(colon + 1).trim()
    }
    val prefix = label.substring(0, colon)
    return if (prefix.equals(issuer, ignoreCase = true)) {
        label.substring(colon + 1).trim()
    } else {
        // issuer 已设但前缀不匹配：与 Rust 一样拒绝
        ""
    }
}
```

调用方（已有 `if (clientId.isEmpty())` 分支）会把它转为失败信息，无需再改。

### 验证

- 单元测试 `OtpAuthUriTest`：补一条 `label=alice:bob&issuer=NexaPipe`
  被拒。

## 风险点

- H1 涉及 `AuthConfig` 写入磁盘：现有 `config_watcher` 是单方向 reload，
  写回需要小心保留 TOML 中其它表的格式/注释。可以参考 `toml_edit` 而非
  `toml::to_string`。
- H2 路线 B 需要客户端签名，服务端验签；如果两端的 secret 取自
  `auth.clients.<id>.secret`，需确认 `totp_rs::Secret` 与 HMAC 库的字节序。
- H3 引入 androidx.security 会增大 APK ~150KB，需要在 `app/build.gradle.kts`
  里加依赖；如不接受可直接走 (3) 的最小方案。
- H4 的方案 A 改 `onResult` 签名，会影响所有调用点（目前只有
  `VpnControlScreen.kt` 两处）。
